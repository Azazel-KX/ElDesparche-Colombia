5. TABLA: USUARIO
==============================================================================================================================
Descripción: Supertipo de las personas de la plataforma (administradores, clientes y agentes). Guarda los datos comunes y las
             credenciales de acceso (correo y contraseña).
Clave primaria: (numero_identificacion)

Campo                    Tipo                   Nulo Clave   Default              Entrada  Descripción
------------------------ ---------------------- ---- ------- -------------------- -------- ------------------------------
numero_identificacion    VARCHAR(20)            NO   PK                           Texto    Número de identificación (cédula,
                                                                                           pasaporte, etc.). Identifica al
                                                                                           usuario.
tipo_identificacion      tipo_identificacion_t  NO                                Lista    Tipo de documento: CC, CE, PAS, PPT
                                                                                           o NIT.
tipo_usuario             tipo_usuario_t         NO                                Lista    Perfil del usuario: ADMIN, CLIENTE
                                                                                           o AGENTE.
nombre                   VARCHAR(80)            NO                                Texto    Nombres del usuario.
apellidos                VARCHAR(80)            NO                                Texto    Apellidos del usuario.
correo                   VARCHAR(100)           NO   UQ                           Texto    Correo electrónico; es el usuario
                                                                                           del inicio de sesión.
contrasena_hash          VARCHAR(255)           NO                                Sistema  Contraseña protegida con hash
                                                                                           (bcrypt); nunca en texto plano.
direccion                VARCHAR(200)           NO                                Texto    Dirección de residencia.
fecha_registro           TIMESTAMP              NO           NOW()                Sistema  Fecha y hora en que se registró el
                                                                                           usuario.
id_ciudad                INTEGER                NO   FK                           Lista    Ciudad de residencia. →
                                                                                           CIUDAD.id_ciudad
CONSTRAINT               ck_usuario_documento_formato SÍ                                Texto

Unicidad compuesta:
  - UNIQUE (numero_identificacion, tipo_usuario)

Restricciones y reglas:
  - La PK es numero_identificacion: un mismo número no puede estar registrado dos veces, aunque cambie el tipo de documento.
  - numero_identificacion normalizado (solo mayúsculas y dígitos) y con el formato de su tipo: CC 6–10 dígitos, CE 4–10, PPT
    5–10, NIT 9–10 sin dígito de verificación, PAS 5–15 alfanuméricos.
  - El documento (número y tipo) no se edita salvo corrección explícita: SET LOCAL app.corregir_documento = 'on'. Las FK
    tienen ON UPDATE CASCADE.
  - correo UNIQUE y con formato válido; es el usuario del inicio de sesión.
  - tipo_usuario decide la tabla de subtipo; (numero_identificacion, tipo_usuario) UNIQUE para la FK compuesta de los
    subtipos.
  - Trigger diferido: todo usuario debe tener su fila en ADMIN, CLIENTE o AGENTE al hacer COMMIT.
  - Nombre completo se separa en nombre y apellidos (1FN).

Relaciones:
  - USUARIO N:1 CIUDAD.
  - USUARIO 1:N TELEFONO_USUARIO.
  - USUARIO IS-A ADMIN | CLIENTE | AGENTE (total y disjunta).
  - USUARIO 1:N VERIFICACION (relación Comprueba).

==============================================================================================================================
Descripción: Evento o espectáculo registrado por un agente. Siempre tiene un estado y una ubicación; solo tiene causa cuando
             está cancelado.
Clave primaria: (codigo)

Campo                    Tipo                   Nulo Clave   Default              Entrada  Descripción
------------------------ ---------------------- ---- ------- -------------------- -------- ------------------------------
codigo                   VARCHAR(20)            NO   PK                           Texto    Código único del evento (ej.
                                                                                           EVT-2026-0001).
nombre                   VARCHAR(150)           NO                                Texto    Nombre del evento.
descripcion              TEXT                   SÍ                                Texto    Descripción del evento.
categoria                VARCHAR(40)            NO                                Texto    Categoría del evento: musica,
                                                                                           teatro, danza, circo o comedia.
url_imagen               VARCHAR(255)           SÍ                                Archivo  Ruta o URL de la imagen del evento.
fecha_hora_inicio        TIMESTAMP              NO                                Fecha    Fecha y hora de inicio.

                                                                                           finalización.

                                                                                           restricción).
observaciones            TEXT                   SÍ                                Texto    Observaciones del evento.
estado                   estado_evento_t        NO           'Programado'         Lista    Estado: Programado, En Boletería,
                                                                                           En Vivo, Finalizado o Cancelado.

                                                                                           evento.

id_ubicacion             INTEGER                NO   FK                           Lista    Lugar de realización. →
                                                                                           UBICACION.id_ubicacion

                                                                                           AGENTE.numero_identificacion

                                                                                           está cancelado. →
                                                                                           CAUSA_CANCELACION.id_causa

Restricciones y reglas:
  - fecha_hora_fin > fecha_hora_inicio.
  - CHECK: estado = Cancelado si y solo si id_causa no es nulo; la causa debe aplicar a EVENTO o AMBOS (trigger).
  - La suma de numero_entradas de las reservas no canceladas no puede superar capacidad_total (también al bajar la
    capacidad).
  - Solo los agentes registran eventos: id_agente referencia a AGENTE.
  - La ciudad del evento no se guarda: se obtiene por UBICACION → CIUDAD.

Relaciones:
  - EVENTO N:1 UBICACION.
  - EVENTO N:1 AGENTE.
  - EVENTO N:1 CAUSA_CANCELACION (opcional).
  - EVENTO 1:N RESERVA (relación Ofrece).

  - valor_total = numero_entradas × precio del evento vigente al reservar; no se recalcula si el precio cambia después.
